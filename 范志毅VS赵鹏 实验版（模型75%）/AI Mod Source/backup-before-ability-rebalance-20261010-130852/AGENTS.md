# 项目验证要求

用户要求每次修改都必须编译并在隔离的游戏副本中运行测试，检查修改后的行为和受影响的正常玩法，再安装正式构建。检查日志中的异常；测试失败应修复并重新运行。

正式游戏不得包含测试入口、自动测试组件或为测试设置的冻结球员逻辑。测试通过后安装，并核对工作源码与实际游戏目录中的文件一致。

同步更新 32 位原版和模型 75% 实验版，保留各版模型、球门和球路差异。64 位版按用户要求忽略。

用户在 2026-10-09 明确要求：以后都不更新 GitHub。不提交、推送或制作 GitHub 更新包，除非用户以后明确改变这个要求。

用户在 2026-10-09 要求：每次修改 AI，都必须加入范志毅和赵鹏完整自我对战，通过原有输入、动作和真实碰撞进行连续攻防。记录每次进球和失球，将进球视为成功、失球视为失败，用实战结果评估和调整策略。保留有用的单人专项测试；自我对战是额外的必需验证，不能省略。
每次 AI 修改的最终自我对战验证，32 位原版与模型 75% 实验版必须各完成双方累计 2000 次真实入球（总共 4000 球）。策略修改后重新计数，不得混合不同策略凑数。先修复并验证地滚球紧急回防僵直，再启动正式自战。

用户在 2026-10-09 本轮明确改为：修复完成后不再自战，专项与正常玩法验证通过后直接本地发布。本次发布豁免每版 2000 球验证；以前试跑球数不得冒称为最终验收。

用户在 2026-10-10 要求通过与现版本自战增强范志毅 AI。上次免自战仅适用于上次发布；本轮恢复每版最终 2000 次入球验证。固定现版本赵鹏 AI 和球员技能作为对手，只增强范志毅决策，保留当前正式版作对照。不更新 GitHub，忽略 64 位。
